Generate concrete examples that specifically illustrate the HIGHLIGHTED FRAGMENT. The surrounding lesson is provided only as background — do not produce examples about the rest of it.

CHOOSE THE EXAMPLE STYLE based on what kind of thing the fragment is. Decide once before writing anything; do not mix styles.

  - If the fragment names a CATEGORY of named instances — a class, type, family, or kind whose members are commonly referred to by their own names in the field — produce ONE BLOCK PER NAMED INSTANCE, 3–5 instances total. Each block's body is one or two sentences naming the instance and stating what distinguishes it from the others. Do NOT walk through a fabricated multi-step scenario for an instance; the learner wants to see the instances themselves, not invented narratives around them.

  - If the fragment names a PROCEDURE, ALGORITHM, or CALCULATION — a series of steps applied to inputs to produce an output — work one or two examples end-to-end. State the input, label each step as you go, give the result. One worked example is enough when it cleanly demonstrates the procedure; offer a second only when an edge case or contrasting input is genuinely informative.

  - If the fragment names a CONCEPT, PRINCIPLE, or MECHANISM — an idea or relationship that explains why or how something occurs — illustrate with one or two short scenarios that show the idea in operation. Keep each scenario tight: a few sentences at most.

  - If the fragment names a RULE, CLASSIFICATION, or DEFINITION — criteria for membership or behaviour — give 2–3 instances that satisfy it. Add a single counter-instance only when the contrast genuinely sharpens the rule.

Quality over quantity. If the fragment's category has four obvious instances, four is the right count — don't pad to fill a quota. If one worked example fully demonstrates a procedure, one is enough.

Output ONLY the examples — no preamble, no summary of the lesson, no closing remark. Start directly with the first example.

CRITICAL: each example MUST be wrapped in its own <div class="ask-ai-block">. The wrapper is non-negotiable even if you only produce one example — it's how the app distinguishes individual examples so the learner can pick which ones to keep. Output structure for each example:

<div class="ask-ai-block">

For a procedure, concept, or rule the phrase is a short label naming the worked example, scenario, or instance being shown. Derive the phrase from the highlighted fragment and the example's content, not from the wider lesson.
