Test cases:
  - PBKDF2 password KEK derivation is deterministic (same password+salt ->
    identical 32-byte key) and salt-sensitive (different salt -> different key).
  - password verification hash is deterministic and verifies with
    safeEqualPaidDeckPasswordHash; a wrong password fails the compare.
  - safeEqualPaidDeckPasswordHash returns false (never throws) on malformed input.
  - generatePaidDeckPasswordSaltBase64 returns a fresh 16-byte base64 salt.
  - isLicenseActive: ACTIVE + no expiry (epoch-zero FOREVER) -> true;
    ACTIVE + future expiry -> true; ACTIVE + past expiry -> false;
    non-ACTIVE status -> false.
  - isEncryptedField recognizes the {__enc:1, ivBase64, ciphertextBase64}
    envelope and rejects plain strings / nulls / partial objects.
  - encryptEntityContent encrypts a card's question/answer (each becomes an
    encrypted envelope) and leaves ids/tags/progress untouched; the source
    object is not mutated.
  - restorePlaintextContent overlays the server's authoritative plaintext over
    an incoming (ciphertext / tampered) entity on push.
  - LicenseClientView.sanitize strips _id and every SECRET_FIELDS entry
    (wrapped/server keys, password hash/salt) while keeping public fields, and
    does not mutate the source; null / non-object passes through.
  - LicenseClientView.sanitizeMany maps sanitize over an array and returns []
    for a non-array.
  - PaidDeckEntityTooLargeError is an Error carrying name / entityId / sizeBytes
    and a message that names the entity and byte count.
  - RateLimiter.consume allows up to the configured limit within a window then
    rejects (allowed=false, remaining clamped at 0, retryAfterSeconds >= 1), and
    throttles distinct keys independently.
  - MaintenanceWindow.isActiveAt is inclusive of start, exclusive of end, and
    false outside or when dates are missing/invalid.
  - MaintenanceWindow.isUpcomingWithin is true only when start is in the future
    and within the lead window; false once already started.
  - MaintenanceWindow.toJson / fromJson round-trip preserves the fields (dates
    as ISO strings); fromJson(null) -> null.
  - CreditDealPayment.fromJson(toJson(x)) preserves the stored id (restored via
    _restoreId_id) and every field bit-for-bit; amountMinor coercion clamps
    negatives to 0 and parses to integer minor units; currency truncates to 8
    chars; an out-of-range status enum coerces to the first valid member.
  - PeriodicCreditAssignment.fromJson(toJson(x)) is likewise id-stable; amount
    clamps negatives/NaN to 0; an empty name becomes null and a long name
    truncates at 256; dayOfWeek clamps to [0,6], dayOfMonth to [1,31],
    intervalDays to >= 0; an invalid status coerces to the first enum member.
  - LicenseFieldPreserver.carryForwardBuyerScopedFields keeps a MASTER-key
    rotation from destroying buyer-scoped state: the per-license content key and
    both its wraps (server + password) and contentKeyVersion survive; the
    paid-deck password hash/salt survive; downloadedContentVersion survives;
    additionalData.instances (the manage-copies registry) survives; issuedAt
    stays at the acquisition date. The freshly rotated keyVersion and
    wrappedKeyBlob are NOT reverted. A legacy document with none of these fields
    yields model defaults rather than undefined, and a malformed additionalData
    (string or array) becomes an empty object. One case asserts the premise that
    makes the class load-bearing: DeckLicense.toJson emits every one of those
    fields, so persistLicense's whole-document $set would otherwise blank them.
  - Sync.PAID_PROTECTED_TYPE_COLLECTIONS lists the entity types whose content the
    server overlays back onto every incoming push. CONTENT_OVERLAY must be ABSENT
    (an overlay is a learner's own edit to their own copy; protecting it would
    silently revert every edit on the next sync) while DECK / CARD /
    STUDY_MATERIAL / MOCK_TEST must all stay present.
  - encryptEntityContent returns a CONTENT_OVERLAY unmodified: its `value` is
    already a ciphertext envelope written by the client, so a branch there would
    double-encrypt it beyond recovery.
  - PaidDeckContentFingerprint.compute hashes only the SELLER-authored content of
    an entity, so a content update can tell per entity whether the publisher
    actually changed it. Ids and progress are excluded (they differ between the
    master and a buyer's copy); whitespace reflow and buyer-authored Ask AI markup
    are normalised away, so neither costs the buyer their progress. An entity type
    with no fingerprintable content returns "".
  - PaidDeckContentUpdatePlanner.plan classifies every entity on an update:
    same id + same fingerprint -> CARRIED (progress, history and the buyer's own
    edit kept), same id + changed fingerprint -> RESET, id only in the new version
    -> ADDED, id only in the old -> REMOVED (tombstoned, cascading its overlays).
    A missing fingerprint on either side RESETS rather than carries — an unproven
    match would attach scheduling state to unverified text. Null/undefined inputs
    yield an empty plan.
  - LicenseContentVersionResolver decides whether to offer a copy an update.
    A downloadedContentVersion of 0 means "unknown, assume current" and is never
    offered an update (every licence predating content versioning reads 0, so a
    naive comparison would tell EVERY existing buyer to update and reset their
    progress for nothing) — needsBackfill flags it for a lazy write-on-read
    instead. A genuinely older version IS offered one. Per-copy versions win over
    the license-level value, since copies update independently; junk and negative
    values normalise to 0.

Notes:
  - Pure Security classes and the hand-written MaintenanceWindow model are
    catalogued here. Most other Dock model classes (User, Device, PaidDeck, ...)
    generate a random UUID in their constructor AND do not restore it on load, so
    their toJson/fromJson are not bit-for-bit deterministic; their field coercion
    is validated indirectly by the endpoint suite rather than duplicated here.
  - CreditDealPayment and PeriodicCreditAssignment are the exception: although the
    constructor generates a random UUID, fromJson restores the persisted id, so a
    fromJson(toJson()) round-trip IS deterministic. They are catalogued here both
    for that round-trip and because they carry money-/credit-amount clamping that
    is security-relevant (a buyer must never widen an amount or grant cadence by
    tampering with the stored document).

Folder "Static-only isolation guarantee":
  - A request to a protected API path with an INVALID sessionId cookie is still
    rejected (401/403), proving the cookie is validated against the store.

Intentional public exception NOT exercised by the suite:
  - POST /Webhooks/Razorpay and POST /Webhooks/Zoho are session-less but signed
    (each validates a payment-provider signature, not a cookie) and side-effecting,
    so the automated suite does not POST to them. They are the non-static
    unauthenticated routes, documented here. (The OAuth flow endpoints /Login,
    /Login/Callback and /Logout are likewise not probed: they are redirect /
    cookie-clearing routes, not JSON API surface.)

Notes:
  - The collection asserts on STATUS CODES and the public/protected boundary,
    not on business payloads (which need seeded data + credits). This keeps the
    suite deterministic and side-effect free against a running server.
  - DB-DEPENDENT 5xx: the public data routes (/LegalDocuments, /PaidDecks/Library,
    /PaidDecks/Filters, /PaidDecks/Search) and the invalid-cookie session lookups
    hit MongoDB; without a reachable database they return 500 and those few cases
    fail. Against a DB-backed server they return 200 / 401 and pass. This is an
    environment limitation, not an auth-boundary regression -- the anonymous
    401/403 rejection of every protected route is asserted independently of the DB.
  - BASE_URL defaults to http://127.0.0.1:3000; override via the environment file
    or the BASE_URL env var.
